# Images : choix du moteur, images depuis TOUTES les salles, ComfyUI local et carte graphique

À installer avec : ComfyUI (session locale) et les deux adresses de Crew `POST /chef/liberer` et `POST /chef/reprendre`. Sans ces adresses, ComfyUI se dégrade proprement (voir « Carte graphique »).

## A. Menu du moteur (page Images ET fenêtre des salles)
- Un vrai `<select>` accessible, avec deux groupes : **Nuage** (Grok, Gemini, OpenAI) et **Local** (ComfyUI). Chaque entrée affiche son prix par image (« ≈ 0,020 $ », « gratuit ») ; une entrée indisponible reste visible, grisée, avec sa raison (clé absente, quota, ComfyUI éteint, confidentialité, plafond, carte à libérer).
- Second menu **Modèle** : xAI = les identifiants « grok-imagine-image* » lus dans `GET /v1/models` (jamais les vidéos, ni grok-4) ; ComfyUI = les checkpoints lus dans ComfyUI ; OpenAI et Gemini = un modèle fixe.
- **Choix par défaut** : le dernier utilisé (mémorisé côté serveur, par utilisateur du Centre : identité Tailscale à distance, « local » sinon, fichier `images_prefs.json`) ; sinon ComfyUI s'il répond, sinon xAI. Un moteur du nuage n'est jamais proposé par défaut pour du contenu confidentiel.
- **xAI corrigé** : modèle par défaut `grok-imagine-image` (plus `grok-2-image`), réponse lue avec `mime_type`, **coût réel** = `usage.cost_in_usd_ticks × 1e-10` (0,02 $ par image chez vous), dépense enregistrée comme réelle (`estime: non`) ; repli sur l'estimation (0,02 $) seulement si la réponse ne donne pas de coût.
- **Gemini 429** : message « le palier gratuit de Google n'inclut pas la génération d'images (facturation Google requise). Rien n'a été facturé. », moteur grisé 10 minutes avec cette raison, jamais de message brut ni de plantage.

## B. Images depuis toutes les salles
- **B1 (commande explicite)** : bouton « 🎨 Image » dans la barre de saisie de chaque salle, et commande `/image <description>` (elle ouvre la fenêtre, description préremplie). La fenêtre : mêmes menus qu'en A, format, nombre (1 à 4), coût estimé, confirmations demandées par le serveur (seuil, carte graphique). L'IA de la salle n'est pas appelée ; rien n'est facturé par elle. L'image s'affiche DANS la conversation : bulle « 🎨 Image générée » (vignettes, télécharger, supprimer, **régénérer**, moteur, modèle, coût réel), enregistrée dans l'historique (elle réapparaît à la réouverture) ET dans la galerie (un seul stockage : le même fichier). Fonctionne dans les 7 types de salles et les salles de modèles LM Studio.
- **B2 (l'IA demande une image)** : la consigne de CHAQUE salle (salles API, LM Studio, Claude/Codex/Gemini par programme, Crew) contient une phrase expliquant le bloc `[[IMAGE]] taille: … description: … [[/IMAGE]]`. Le Centre repère le bloc dans la réponse, au fil du flux (même coupé n'importe où), le **retire du texte affiché** et montre une **carte** « 🎨 L'IA propose de générer une image » avec la description COMPLÈTE, le format, le moteur par défaut et le coût, et les boutons [Générer] [Modifier] [Ignorer]. **Jamais d'exécution automatique** : seul le clic lance la création. Un bloc dans un message de l'utilisateur, une pièce jointe ou le tiroir est ignoré (seul le texte de l'IA est examiné) ; au plus UN bloc par réponse (les suivants restent du texte, sans effet) ; description de 4 000 caractères au plus ; bloc mal formé ou jamais fermé = affiché tel quel, sans effet ; aucune proposition en table ronde. La carte se souvient de son état (proposée, générée, ignorée).
- **B3 confidentialité (refus par le SERVEUR)** : conversation privée, case « confidentiel », mode Confidentiel / Ultra-confidentiel, contenu privé du tiroir → seul ComfyUI ; le nuage est refusé (403) par `images.lancer`, pour B1 comme pour B2. La description n'est jamais dans les journaux ni les reçus (seulement avec l'image, sur le PC).
- **B4 coûts** : estimation avant, confirmation au-dessus de `seuil_image_usd`, plafonds jour/mois, dépense « Images (nuage) » au coût réel quand il est donné. **Une création à la fois** : les autres sont « en attente » (position) avec un bouton **Annuler** (en attente ou en cours).
- Un repère « [image générée : id] » reste dans l'historique envoyé à l'IA ; l'image n'est jamais renvoyée à une IA sans que vous la joigniez. Une création ratée ajoute un message d'erreur à la conversation (exclu de l'historique envoyé à l'IA) ; à la réouverture, les créations en cours ou en attente sont retrouvées.

## C. ComfyUI et carte graphique (16 Go partagés avec le chef)
- Travail ComfyUI avec le chef chargé (`GET /chef.chef_charge`) et Crew actif : **confirmation** demandée par le serveur (« Crew sera indisponible pendant la création : la carte graphique doit être libérée. Continuer ? »), puis `POST /chef/liberer` → attente de la fin par `GET /chef` → création → `POST 127.0.0.1:8188/free {"unload_models": true, "free_memory": true}` → `POST /chef/reprendre`. Pas de reprise si : Mode jeu en cours, Crew arrêté, case « laisser la carte libre ensuite », ou un autre travail ComfyUI attend dans la file (il reprendra à la fin). Crew arrêté : aucune adresse de Crew n'est appelée. Le Centre ne charge ni ne décharge JAMAIS LM Studio.
- **404 sur /chef/liberer** : le travail est refusé avec « Libérez la carte graphique d'abord (page Chef d'équipe ou Mode jeu) », et ComfyUI reste grisé avec cette raison tant que le chef occupe la carte. 409 (travail Crew / table ronde en cours) : message clair, rien n'est lancé ; 503 (LM Studio arrêté) : rien à libérer, on continue.
- Même si la création échoue, la carte est rendue (free + reprise) quand elle avait été libérée.
- **Familles de modèles** (au lieu d'un seul graphe SD 1.5), détectée par le nom du checkpoint : SDXL (1024², 832×1216, 1216×832 ; 28 pas ; cfg 6,5), SD 1.5 (512², 512×768, 768×512 ; 25 pas ; cfg 7), Flux (pas de consigne négative : vecteur nul, FluxGuidance 3,5, cfg 1, 20 pas), inconnu = SDXL prudent. Table modifiable : `familles_comfy.json` dans le dossier des données (valeurs validées, le reste ignoré) ; un test par famille.
- Sécurité : ComfyUI n'est joignable que sur 127.0.0.1 par le Centre ; le Centre relaie les images (téléphone compris) ; aucune exposition par Tailscale.

## Suppositions (à vérifier sur le PC)
- **Formats d'API de Crew** : `POST /chef/liberer` et `/chef/reprendre` répondent 202 `{"changement": {...}}` comme `PUT /chef` ; le suivi se fait par `GET /chef.changement.etat` (termine / echec) ; ils ne touchent jamais aux modèles d'embeddings. Je n'attends PAS la fin de `/chef/reprendre` (le chef se recharge en arrière-plan ; le suivi est visible dans la page Chef d'équipe).
- **Détection du Mode jeu** : « Mode jeu en cours » = la séquence Mode jeu est en train de s'exécuter dans le Centre. Une fois finie, Crew est arrêté, donc rien n'est appelé.
- **ComfyUI** : graphes standards (chargeur de checkpoint, textes, image vide, KSampler, décodeur, enregistrement) ; Flux via un checkpoint tout-en-un (fp8) ; les échantillonneurs par famille (dpmpp_2m/karras, euler/normal, euler/simple) sont des valeurs courantes à ajuster dans `familles_comfy.json`. Un modèle Flux en deux fichiers séparés (UNET + CLIP + VAE) n'est pas géré.
- **Coûts** : xAI = réel (ticks) ; Gemini 0,039 $ et OpenAI 0,042 $ = estimations (marquées « indicatives »).
- **Images vers Grok/Gemini/ChatGPT** (pièces jointes, livraison précédente) inchangées.
- **Crew** peut répondre avec un bloc [[IMAGE]] comme les autres salles (la consigne est dans les messages qu'on lui envoie) ; je n'ai pas pu vérifier ce que son serveur fait de la consigne système.
- **Phase 2 non faite** : « Modifier cette image » (xAI `/v1/images/edits`, ComfyUI image vers image). Le format exact de `/v1/images/edits` n'a pas été essayé en vrai ; je préfère le brancher après un essai réel plutôt que sur une hypothèse.
